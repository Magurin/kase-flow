# KASE Flow

Платформа корпоративных действий для KASE × Superteam Kazakhstan. **Только Solana Devnet:** облигации Token-2022, выплаты SPL TEST USD, escrow, купоны, частичное и полное погашение, отмена неоплаченного действия, возврат остатка escrow, кабинет инвестора и автопилот.

## Демо

Открыть **http://127.0.0.1:5173/**. API работает на 127.0.0.1:3001. Приложение использует публичную сеть Devnet и её реальное время.

Публичная версия: **https://kase-flow.vercel.app/**. Она читает два демонстрационных выпуска непосредственно из Solana Devnet: завершённый цикл с купонами, частичным и полным погашением, а также открытый выпуск. На Vercel доступны каталог, реестр, начисления, журнал и экспорт публичного аудита. Создание выпусков, выплаты, переводы и автопилот остаются в локальном демо: сервер эмитента хранит тестовые ключи и не предназначен для публичного доступа. Приватные ключи и `.local/` не загружаются в Vercel.

Для обновления списка публичных выпусков после локального размещения запустите `node scripts/generate-public-demo.mjs`, проверьте сгенерированный `api/_public-data.mjs` и разверните новую версию. В модуль включаются только заранее выбранные публичные адреса, метаданные и подписи транзакций.

Проверка публичной версии: `npm run build:hosted`, `node scripts/serve-hosted.mjs`, затем в другом терминале `node scripts/verify-hosted.mjs`. После размещения: `node scripts/verify-hosted.mjs https://kase-flow.vercel.app`. Проверка читает оба выпуска, сравнивает реестр и токены, проверяет изоляцию кэша, журнал, экспорт и запрет записи; транзакции не отправляет. Каталог получает свежие данные Devnet, а при сбое RPC явно помечает сохранённые значения. Журнал объединяет сохранённые записи со 100 последними успешными транзакциями аккаунта.

`uuid` закреплён на 11.1.1 через npm override: `rpc-websockets` загружается Solana SDK через CommonJS, а uuid 14 является ESM-only и вызывает `ERR_REQUIRE_ESM` в Vercel Functions. Версия 11.1.1 поддерживает CommonJS и содержит исправление проверки границ буфера. Тест запускает импорт API с `--no-experimental-require-module`, чтобы воспроизводить это ограничение сервера.

[Развёрнутая программа в Solana Explorer](https://explorer.solana.com/address/4r48EMFeGkNMyrhEvoZgkmQJrdW9VjaatRpH9y677nq1?cluster=devnet).

TEST USD не имеет денежного обеспечения. STPE.28 — тестовая облигация вымышленного эмитента. Все записи и переводы токенов проверяемы в Devnet; реальные деньги не используются.

## Запуск

Нужны Node.js 22+. Для сборки программы дополнительно Rust и Solana CLI/cargo-build-sbf. Docker и локальный валидатор не требуются.

```powershell
npm ci
npm run dev
```

Ключи и конфигурация текущего Devnet-выпуска находятся в игнорируемой `.local/devnet/`. На новой машине сначала:

```powershell
npm run chain:build
npm run devnet:deploy
npm run dev
```

Деплой проверяет genesis hash Devnet. Если нужны тестовые SOL, скрипт выводит адрес для [Solana Faucet](https://faucet.solana.com). Для обновления: `npm run devnet:deploy -- --upgrade`. Для нового выпуска на внешний адрес: `npm run devnet:deploy -- --new --wallet PUBLIC_KEY`. Mainnet RPC не допускается для отправки транзакций.

Для production-сборки интерфейса: `npm run build`, затем `npm start`; открыть http://127.0.0.1:3001.

## Рабочее пространство эмитента

Откройте «Выпуски эмитента» → «Новый выпуск». Мастер сохраняет условия и реестр как версионируемый черновик. Укажите название эмитента, тикер, номинал, ставку, частоту, число купонов и срок; распределите весь объём между инвесторами и подтвердите допуски. Пустой адрес создаёт тестовый кошелёк, заполненный — распределяет токены на указанный внешний адрес.

«Проверить и утвердить» фиксирует версию и SHA-256 условий на локальном сервере. Любое изменение снимает утверждение. «Разместить в Devnet» создаёт отдельный инструмент, Token-2022 облигации и полностью обеспеченный тестовыми TEST USD escrow. Предыдущие выпуски сохраняются в каталоге.

Внутри выпуска: «Календарь и контроль» показывает обязательства, бюджет, состояние автопилота, сверку реестра и токенов, а также экспорт отчёта с условиями и историей согласований. Форма корпоративного действия показывает предварительные начисления и покрытие escrow. После частичного погашения будущие купоны рассчитываются по оставшимся облигациям.

Каждый выпуск имеет отдельные конфигурацию, ключи тестовых держателей, журнал и настройки автопилота в `.local/devnet/issues/<state>/`. Выбор в интерфейсе хранится в браузере, запросы явно указывают инструмент. Автопилот последовательно обслуживает все включённые выпуски, а не только открытый в браузере.

Сервер в `npm run dev` запускается без автоматического перезапуска: изменение файлов не должно прерывать отправку транзакций. После изменения серверного кода перезапустите команду вручную; горячее обновление интерфейса работает.

При прерванном размещении черновик получает статус «Требует проверки». Адреса и ключи сохраняются до отправки и между этапами. «Сверить с сетью» восстанавливает каталог, если размещение фактически завершилось; незавершённую многошаговую подготовку нельзя повторять автоматически. Подробности: `docs/WORKSPACE.md`.

## Как тестировать

1. Нажать «Новый демо-выпуск» внизу боковой панели. Четыре держателя получают 400 / 300 / 200 / 100 облигаций Token-2022. Escrow получает 1 200 000 TEST USD.
2. Выпуск из интерфейса действует **10 минут**; четыре купона наступают каждые 2,5 минуты. Деплой-скрипт создаёт исходный выпуск на 24 часа. Время всегда берётся из Devnet.
3. До record date можно перевести облигации с подписью держателя.
4. В разделе «Корпоративные действия» нажать «Новое действие» и запланировать купон №1, дождаться даты фиксации, нажать «Зафиксировать реестр», затем «Инициировать расчёт» и «Выплатить» по каждому держателю. Десять облигаций дают 500 TEST USD.
5. До maturity создать частичное погашение 20%. Выплата и сжигание токенов выполняются атомарно.
6. Завершить оставшиеся купоны и полное погашение. Финальный principal недоступен до выплаты всех купонов.
7. После полного погашения в разделе «Календарь и контроль» вернуть остаток escrow эмитенту.
8. Открыть журнал, перейти в Explorer, скачать JSON-аудит.

Запланированное действие можно отменить, пока по нему не проведено ни одной выплаты: record date снимается, переводы разблокируются. Дата фиксации не может быть позже срока купона или погашения более чем на 30 дней, поэтому опечатка в дате не заблокирует выпуск.

## Сроки и купоны

Купон за период равен годовой ставке, делённой на число выплат в год. Номинальный срок выпуска поэтому равен «купонов ÷ выплат в год» лет: 4 купона при двух выплатах в год означают 2 года. При создании выпуска выбирается режим времени:

- **Демо** - номинальный срок сжимается в 5 минут-1 день Devnet, суммы купонов те же, что при реальном сроке;
- **Реальный календарь** - выпуск живёт в Devnet весь номинальный срок, даты купонов настоящие.

Автопилот выполняет наступившие купоны и погашение по расписанию; частичное погашение планирует оператор. Он читает on-chain статусы, пропускает оплаченные строки и продолжает после пополнения escrow. Включение и ошибки сохраняются на диске. Публичный RPC иногда ограничивает частоту: балансы запрашиваются пакетно, интерфейс получает данные с задержкой до восьми секунд.

## Кошелёк

В кабинете инвестора подключить Phantom или Solflare. Новый адрес может получить 100 облигаций в новом выпуске. Переключите кошелёк в Devnet. У облигации есть метаданные Token-2022 (название и тикер выпуска), у TEST USD - метаданные Metaplex, поэтому кошелёк показывает их по имени. Выпуски, созданные до этого обновления, остаются без метаданных.

Получение выплаты требует подписи кошелька, комиссию спонсирует тестовый эмитент. Сервер проверяет точное сообщение, подписи и срок запроса. Приватный ключ подключённого кошелька не запрашивается. Для тестовых инвесторов без расширения выплату подписывает серверный тестовый эмитент.

## Проверки

`npm run test:workspace` проверяет полный новый процесс через API и реальный Devnet (~6 минут, тестовый SOL): условия с шестью десятичными знаками, размещение, перевод, частичное погашение, автоматический купон и финальное погашение, изоляцию предыдущего выпуска и экспорт отчёта.

```powershell
npm test
npm run test:program
npm run build
npm run test:chain
```

`test:program` собирает программу и прогоняет её в LiteSVM вместе с настоящими SPL Token и Token-2022: полный цикл выплат, блокировку на record date, отмену, возврат escrow, границы дат и запрещённые расширения mint. Занимает секунды. На Windows host-тесты требуют MSVC-тулчейн Rust (`cargo +stable-x86_64-pc-windows-msvc test ...`), GNU-тулчейну без MinGW не хватает `dlltool`.

`test:chain` создаёт отдельный инструмент в Devnet и проверяет метаданные токенов, отмену действия, два купона, частичное и полное погашение, фактические балансы, нулевую итоговую эмиссию и возврат остатка escrow (~5 минут, расходует тестовый SOL). Подтверждённый прогон записан в `artifacts/devnet-evidence.json`.

Дополнительные долгие проверки: `npm run test:security` (~10 минут), `npm run test:e2e` (полный цикл в браузере, ~12 минут), `npm run test:wallet` (тестовый wallet provider с настоящими подписями, ~6 минут). UI-тесты создают новый выбранный выпуск; не запускайте их одновременно с ручным демо. Эти скрипты используют только время и RPC Devnet.

`npm run test:e2e` записывает `artifacts/demo.webm`. Быстрая запись обзора интерфейса — `artifacts/devnet-tour.webm`; она не заменяет полную запись сценариев.

## Границы прототипа

До 16 держателей и 16 действий на выпуск. Допуски и утверждение условий выполняет один доверенный оператор; это не интеграция KYC, не мультиподпись и не промышленное разграничение доступа. Размещение распределяет тестовые облигации; сбор денег по заявкам не реализован. Закрытый реестр; переводы проходят через программу. Частичное погашение округляется до целой облигации вниз, денежные суммы - до микро-единицы TEST USD; escrow пополняется с резервом в одну микро-единицу на держателя и период, чтобы округление после переводов не сорвало последнюю выплату. Нет банка, KASE API, KYC и реальных ценных бумаг. Купоны не пересчитываются по фактическому числу дней (day-count), налоги и НКД не моделируются.

Модель доверия - кастодиальная: ключи тестовых держателей хранит сервер, эмитент один, мультиподписи и ролей нет. API принимает запросы только с loopback-адресов (Host проверяется) и рассчитан на доверенный компьютер; промышленная авторизация и управление ключами не реализованы.

Ключи и RPC credentials не входят в Git или ZIP. Архив исходников собирается командой `npm run package`. SPL SDK использует `vendor/bigint-buffer`: ограниченную JS-реализацию четырёх преобразований без уязвимого native-модуля; версия 1.1.6 обозначает локальную совместимую реализацию.

- `docs/TECHNICAL.md` — архитектура, формулы и модель доверия.
- `docs/VERIFICATION.md` — результаты проверок.
- `docs/SUBMISSION.md` — описание для подачи.
- `npm run rpc:check` — только чтение Supanode; этот Mainnet endpoint не используется для демо-транзакций.

Публикация исходников/видео, регистрация команды в Colosseum и подача заявки остаются действиями участника.
